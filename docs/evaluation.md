# AI Agent 离线评估体系

> 目的:用可复跑的自动化评估证明 Agent 效果(Intent / 工具选择 / 实体解析 / 防编造),
> 而不是靠人工点七条问题目测。所有指标来自真实 LLM 运行,报告落盘 `server/evals/reports/`。

## 首次基线(2026-09-10,glm-5.3-flash,29 例 / 31 轮)

完整报告:`server/evals/reports/run-2026-09-10-06-34-summary.md`。核心数字与解读:

| 指标 | 值 | 解读 |
|---|---|---|
| Intent / Decision 准确率 | 100% / 100% | 意图与参考决策语义全部正确 |
| 实体/Symbol 解析 | 96.6% | 唯一 miss 是"全持仓风险"用例把 symbol 绑到风险最高的一只(口径争议,非错误) |
| 工具选择(宽松) | 89.7% | 必选全含 ∧ 无禁用,基本达标 |
| 工具选择(严格) | 44.8% | **全部失败源于"多调白名单外工具",无一例漏调必选工具** |
| 未查先答率(幻觉风险) | 0% | 要求查证的轮次零漏查;防编造闸门 0 次触发(无需触发) |
| 无效工具调用率 | 0% | 参数 JSON 解析零失败 |
| 平均工具调用 / LLM 轮次 | 4.87 / 2.87 | 并行调用下单次分析 2-3 轮完成 |
| 延迟 mean / p50 / p95 | 74.4s / 65.5s / 164.0s | 思考开满质量优先的已知代价 |

**行为发现(评估的真实价值)**:
1. 模型倾向"多查不漏查":买入/加仓会额外查 `get_account`(可用资金)、止盈会查 `get_trade_history`(当初买入理由)——从教练视角合理,但超出用例预设白名单,严格口径因此偏低;后续迭代 prompt 加节制约束或校准用例白名单后复跑对比;
2. 真实缺陷两处:无意义输入(ED-002)被发散成 8 次工具调用;多轮对话第二问(ED/MT-002·T2)重复 `search_stock`(铁律 2 允许沿用已解析实体,模型未沿用)——均为"浪费"而非"错误";
3. 多轮防过期重查(MT-001·T2"卖一半回款"重查持仓)行为正确。

## 三层测试金字塔

| 层 | 对象 | 方式 | 位置 |
|---|---|---|---|
| L1 | 工具函数(解析/缓存/容错) | vitest,mock 上游 | `server/tests/*.test.js` |
| L2 | Agent 编排逻辑(循环/闸门/触顶/修复) | vitest,mock LLM | `server/tests/ai-agent.test.js` |
| L3 | **Agent 端到端效果(本文件主题)** | 真实 LLM + 真实工具,自动评分 | `server/evals/` |

## 目录结构

```
server/evals/
├── cases.json        # 评估用例集(29 例 / 33 轮)
├── fixture/          # 评估前置状态(DATA_DIR 指向此处)
│   ├── account.json  #   现金 41853.14(初始 10 万 − 三笔买入)
│   ├── positions.json#   平安银行 3000 股(两批次)+ 比亚迪 100 股
│   ├── trades.json   #   三笔买入流水(带买入理由备注)
│   ├── watchlist.json / snapshots.json
│   └── chat.json     #   运行时生成,不入库(每用例前清空,用例间隔离)
├── scoring.mjs       # 评分纯函数(单轮断言 + 指标聚合 + markdown 渲染)
├── run.mjs           # runner:零侵入复用 runAgent 的 onEvent 收集实际行为
└── reports/          # run-*.jsonl(逐轮原始明细)+ summary-*.json/.md(入库,真实证据)
```

## 用例集设计(29 例 / 31 轮)

| 类别 | 数量 | 覆盖点 |
|---|---|---|
| general_analysis | 4 | 全名 / 持仓股 / **拼音 byd** / **纯数字代码 600519** 实体解析变体 |
| buy / sell / position / add / reduce | 12 | 各决策 intent;卖出必须查持仓;**未持仓股谈卖出**(SA-003) |
| risk_analysis | 2 | 全持仓必须走批量快照工具(铁律 3) |
| market_query | 2 | 大盘 / 交易时段 |
| qa | 4 | 纯概念问答:**必须零工具**(防编造闸门白名单 + 节制) |
| edge | 3 | 不存在的股票(不编造)/ 无意义输入 / **下单请求必须引导自行操作**(安全边界) |
| multi_turn | 2 组 4 轮 | 第二轮引用数字前必须重查(铁律 1"历史数字过期") |

## expected 字段语义(单轮断言)

| 字段 | 语义 |
|---|---|
| `intent[]` / `decision[]` | 实际值 ∈ 集合 |
| `symbol` | 字段存在(含 `null`)即严格相等;`null` 表示断言"不绑定个股" |
| `toolsMust[]` | 全部被调用过 |
| `toolsMustNot[]` | 一个都不允许出现 |
| `toolsAnyOf[]` | 实际工具集 ⊆ must ∪ anyOf(严格口径第三条件) |
| `requiresToolCalls` | `true` 至少 1 次;`false` 必须 0 次;缺省不判 |
| `factsNonEmpty` | facts 至少一项 |
| `textContainsAny[]` | 回复 JSON 含任一关键词 |

## 指标定义

| 指标 | 公式 / 口径 |
|---|---|
| Case / Turn 通过率 | 全部断言通过的轮占比;case 要求所有轮全过 |
| Intent 识别准确率 | intent 命中预期集合的轮占比 |
| 工具选择准确率(严格) | 必选全含 ∧ 无禁用 ∧ 无预期外工具 |
| 工具选择准确率(宽松) | 必选全含 ∧ 无禁用(允许多调预期外工具) |
| 实体/Symbol 解析准确率 | reply.symbol 与预期一致的轮占比(有 symbol 断言的轮) |
| 最终应答有效率 | runAgent 成功且非 fallback 降级的轮占比 |
| 防编造闸门拦截率 | 触发"拦截"降级的轮占比(防线生效信号,非失败) |
| 未查先答率 | `requiresToolCalls:true` 却零工具的轮占比(**幻觉风险,基础口径**) |
| 无效工具调用率 | 工具参数 JSON 解析失败次数 / 工具调用总数 |
| 工具执行错误率 | 工具执行返回 error 次数 / 工具调用总数 |
| 平均工具调用 / LLM 轮次 / 延迟 | 均值;延迟含 mean / p50 / p95 |

**诚实声明(口径局限)**:
- "未查先答率"是幻觉风险的基础口径(查了 A 编 B 的"张冠李戴"需数字溯源,属后续 P1 迭代);
- LLM temperature=0.3,单次运行存在随机性,报告数字是**本机本次真实结果**而非承诺值;
- 行情/财务数据实时变化,facts 内容不作逐数字断言(防 flaky),只断言结构与来源行为;
- 样本量 29 例,置信区间有限;对比不同 prompt/模型版本时用同一用例集复跑。

## 跑法

```bash
cd server
npm run eval                    # 全量(约 30-40 分钟,真实 LLM)
node evals/run.mjs --only QA-001,GA-001   # 试跑 / 复验单条
node evals/run.mjs --resume     # 中断续跑(增量 jsonl,跳过已完成用例)
```

前置:`~/.stock-learning/ai.json` 已配置(或 `ZHIPU_API_KEY` 环境变量)。
隔离:`DATA_DIR` 指向 `evals/fixture`,与运行中的正式实例(`data/`)互不影响。

## 真实性纪律

1. 报告(reports/)随仓库提交,作为简历量化数据的可查证来源;
2. 简历/文档引用指标时必须注明 用例数 N、模型、日期,与报告文件一致;
3. **禁止**手工修改 jsonl/summary 里的数字;要新数字就复跑。
